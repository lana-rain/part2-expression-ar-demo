# Part 2｜微笑雨特效方向与验收（雨效单项）

## 2026-10-21 当前视觉与持续触发方向

本节取代下方 2026-10-18 的“只在头部附近下雨”方案；下方内容保留为旧版设计和验证历史。现在两朵完整的小云从左右进入，在头顶重叠并渐变为**横跨直播画面顶部的一朵大云**，一次低强度云内透光与细电光后，雨覆盖整个直播画面并落到画面底部；头部附近增加雨滴密度，雨滴碰到随脸部关键点移动的二维发顶轮廓时出现短促扇形飞溅、接触亮点和少量侧发水痕。虚拟镜头玻璃还有短促的入射雨线、局部飞溅小水珠、汇流与弯曲下滑水线，五官附近逐颗淡化，直播控件保持可辨。云聚拢与电光是一次性开场，**雨幕在微笑持续期间保持**；真人头部移动时云与发顶接触点应跟随，不把二维近似描述成真实湿发或头发分割。

大笑烟花也遵循持续规则：烟花弹由画面四周按预制波次持续升空，在头顶、两侧和头部后方分批绽放；较亮火星碰到头部外围时向侧方弹开，带出局部二次碎花，细小火星多数在脸缘消散、少数轻弹，人物五官仍在前景可读。依此前视觉反馈，雨云恢复为发送参考图之前的[彩色蓝紫云](../app/public/effects/smile-rain-cloud-playful-v4.png)，以两朵完整小云从两侧进入，在顶部重叠并交叉淡化为一朵大云；网页保留后续的下缘柔化，避免发顶出现硬边。灰炭云和参考图之后的透光云均为历史版本。自然微笑与大笑演出**互斥**：稳定回到平静后先让当前效果渐退，再冷却 2 秒；直接从微笑变大笑或反向变化时先收束当前效果，再凭新鲜表情帧开始另一效果，不要求经过平静。播放期间继续跟踪人脸位置供 AR 对齐。礼物保留即时送出反馈；当前同类效果可即时升级，不同类效果等待匹配表情。底栏按用户提供的直播截图调整为评论输入、表情、点赞、礼物、分享；实验控制与图像验证位于直播框旁的互动实验台。

新版验收需分别检查全屏雨的画面覆盖、发顶水花和镜头水珠可见性、大笑持续超过旧版九秒时仍继续多点绽放、二次小烟花及脸部可读性、微笑持续超过旧版七秒时雨不中断、雨与烟花切换期间绝不叠加、平静回落后的收束与 2 秒冷却，以及不做平静表情也能直接切换。图像模拟输入位于直播框旁的“互动实验台 → 画面输入”，可选择固定照片、上传图片或播放连续表情视频，经过现有人脸模型与表情规则自动触发 AR，画面仍留在同一直播间。真人表情、不同发型和实体手机的体验仍需现场验证。

## 有据可依的能力，与尚未验证的创意

- TikTok Effect House 官方教程展示了预制动画纹理，并以素材库中的 **Rain Diagonal** 为例，说明可通过交互事件控制雨纹理播放；它证明“预制雨视觉＋触发”是可行的制作方式，**没有证明微笑触发或头顶乌云是平台流行玩法**。[动画特效教程](https://effecthouse.tiktok.com/learn/guides/crash-course/effect-house-101/creating-animated-tiktok-effects)
- TikTok 的 Face Binding 支持将效果绑定到脸部中心、额头等锚点；本 Demo 借鉴“跟随人物”的原则，在已有关键点上定位云层和局部水珠，不宣称调用了 TikTok 原生特效引擎。[Face Binding 文档](https://effecthouse.tiktok.com/learn/guides/workspace/components/ar-capability/face-binding)
- TikTok 的头部分割可隔离头部，但官方同时提示 iOS 上分割性能开销很高。本轮先用轻量的头部轮廓近似与少量接触点，不把“头发真实湿透”列为承诺。[Head Segmentation 文档](https://effecthouse.tiktok.com/learn/guides/workspace/objects/segmentation/head-segmentation)
- 抖音像塑官网明确提到特效、直播等分发场景及直播礼物／互动特效创作。这只说明直播互动是相关创作场景，**不能据此断言“笑召雨”会有流量、传播率或商业收益**。[抖音像塑官网](https://effect.douyin.com/)

## 创意：笑召雨

微笑是直接触发器，送礼不是前置条件。反差感来自“主播一笑，两侧乌云朝主播头顶移动，合拢、轻闪后，雨真的淋向主播的头部”；不是灾害、惩罚或雷击人物。完整动画控制在约 5–7 秒，一次确认的微笑播放一遍；识别信号短暂回落不能让动画卡住或突然重启。观众静音看完，也应看懂表情与天气的因果。视觉重心始终是主播的脸，雨只给表情增加戏剧性。

| 阶段 | 候选节奏（从**确认微笑**计） | 画面要求 |
|---|---:|---|
| 两侧接近 | 约 0–2.15 秒 | 两团预制乌云从画面左、右边界进入，沿曲线移向主播头部上方；有可见位移和轻微浮动，而不是原地缩放。以头部锚点为终点，让开 LIVE、主播名和五官。 |
| 合拢 | 约 2.15–2.75 秒 | 云团在头顶汇合成主体云形，运动减速并随头移动；直播画面的挑战提示在这段视觉线索中退让。 |
| 闪电／天气转折 | 约 2.82 秒，单次短脉冲 | 细小闪电仅在云中或云缘出现；直播画面最多一次低强度冷色提亮，不全屏黑屏、白屏或连续频闪，不击中面部。 |
| 头部局部降雨 | 约 3–6.2 秒 | 雨从云底落向头顶附近，范围明显收束到人物，而不是整屏背景雨。雨滴在头部二维近似轮廓处变成短促飞溅及向两侧滑落的水珠；保留双眼、嘴部和直播 UI 的清晰度。 |
| 收束 | 约 6.2–7 秒 | 雨势与云团退场，水珠短暂留尾后消失。持续微笑不重放；先回到中性、再微笑，才能重新播放完整动效。 |

预制云形、闪电路径、雨丝材质和水珠反馈；运行时只选择预设、决定时机、依据脸部位置摆放和更新少量粒子。脸丢失、摄像头暂停、输入切换或页面退后台时，不得留下悬空的云或继续闪电。减少动态效果设置下应跳过闪电亮脉冲、减轻移动，并保留“微笑触发雨”的可理解反馈。时间轴是表情**确认之后**的视觉时长，不含摄像头授权和表情确认所需时间。

## 必须过的审查

1. **因果与传播钩子：**录制约 7 秒无声竖屏片段，内容包含中性→自然微笑→两侧云移动并合拢→头部下雨。让至少 3 位没看说明的人描述发生了什么；候选通过线是至少 2 人能说出“笑使主播头顶变天／下雨”，而非只说“屏幕有雨”。单帧封面应同时看清主播表情、局部云和雨。此为待做用户测试，不是已达成数据。
2. **主播与直播可用性：**在 390×844 视口以及桌面居中直播预览中检查开场、稳定雨、送礼托盘打开三个时刻；双眼、嘴部、主播信息、评论和礼物入口均可辨认／可点击。云不能长期压在脸上，雨和水珠不能盖住五官或伪装成界面按钮。
3. **触发与复触发：**无礼物也能触发。连续微笑只播一次完整约 7 秒动效，表情短暂波动不重复闪也不中断；中性回落后再笑可重新播放。只张嘴、未识别到脸、暂停输入时不启动新雨。礼物可提升既有雨的细节，但不能替代微笑条件。
4. **跟踪可信度：**头在画面内左右移动时，两侧云以更新的头部位置为汇合目标，降雨与轮廓水珠跟随头部而非固定在屏幕；脸离开画面后及时清除位置依赖元素。当前只能验收二维近似，不得称为精准头发分割、真实淋湿或真实水体物理。
5. **舒适与性能：**实机观察亮脉冲及连续观看 3 分钟，无刺眼频闪、整屏突黑或持续遮脸；记录特效层帧耗时、粒子峰值和内存变化，低性能设备必要时优先降低雨丝／水珠密度。若这些实测未完成，只能称“本地视觉原型”，不能称移动端性能已达标。

先用现有中性／微笑演示片段检查云团入场、合拢、闪电、头部降雨和收束的完整时序，再用获得权限的真人摄像头复核自然微笑、头部移动、失脸和不同光照。合成照片或视频能证明演示链路，不能证明真人识别精度；传播性须经上述无说明观看测试，不能仅凭作者觉得“好看”宣称已验证。

## 当前本地实现与复查（2026-10-18）

当前实现复用同一张预制透明雨云作为左右云团，让它们从屏幕两侧向实时头部锚点移动，合拢后以中心云形承接一次云内闪电；随后局部雨束从云底落向头部。雨滴源头限制在头宽附近，接触发顶二维近似轮廓时生成短促飞溅、水珠及头发边缘亮痕，不再以整屏雨幕表现。头部靠近页面顶部时，云会缩小并移到脸侧，以免盖住眼睛；雨丝按面部近似轮廓留白，直播信息仍可读。提示横幅在云雨线索出现时退让。系统启用“减少动态效果”时采用短时序并跳过闪光。雨云素材在 `app/public/effects/smile-rain-cloud.png`，由内置 imagegen 以“透明底、单朵宽形体积雨云、靛蓝主体、少量青／粉轮廓光、不含雨／闪电／人物／文字”的提示预制，运行时不生成图片。
