# Part 2｜直播间表情 AR 互动原型

这是一个**本地直播间交互原型**：页面按直播观看界面呈现，本机摄像头作为主播画面，实时识别面部表情并播放预先设计的 AR 效果。闭嘴且嘴角上扬的微笑会让两朵云聚拢、闪电并持续下雨，双眼是否眯起都不改变这一归类；只要持续识别到微笑，雨就不会因固定计时到点而停止。持续烟花要求**张嘴并有双眼笑意**，或**手遮住嘴、双侧苹果肌持续上扬且有双眼笑意**，再经短暂多帧确认；只张嘴且眼神平常更可能是在说话，不能据此触发烟花。单纯眯眼、眨眼、抬眉或皱眉也不能单独算大笑。雨滴在发顶附近弹出短暂的小水珠，少量水珠沿侧发滑落，另有稀疏的水滴落到虚拟镜头玻璃后向下流；较亮的烟花火星触及近似头缘后折返，细小火星多数消散、少数轻弹。雨和烟花互斥；表情稳定回到平静后效果平滑收束，再冷却 2 秒。微笑与大笑之间可直接切换：当前效果收束后按新识别到的表情启动另一效果，**不要求主播先恢复无表情**。默认自然互动无需送礼即可触发；礼物后短窗、PK 阶段和主播话题片段是另外三种可切换的场景假设。

当前把直播画面与实验控制分开：左侧保持完整的直播观看界面；右侧“互动实验台”显示输入来源、识别结果、特效进度、摄像头开关和四种触发场景。场景只决定**何时允许开始**一轮演出，表情仍决定雨或烟花以及持续时间；PK、话题片段由手动开关模拟，不接真实平台事件，也不识别讲话内容。宽度较窄时，直播画面占满首屏，实验台排在下方。页面打开后直接请求实时摄像头。**本地开发版与开机预览版**保留图像模拟验证入口，测试素材经过同一人脸模型、表情规则与 AR 特效；`pnpm build` 生成的**公开演示版**隐藏这一入口，并从发布文件中移除测试素材。此原型不连接 TikTok 账号、直播流或支付系统。完整需求见[产品工作说明](../docs/part2-product-brief.md)，效果验证与边界见[验证记录](../docs/part2-demo-validation.md)。公开部署由仓库根目录的 GitHub Pages 工作流完成；实际 HTTPS 地址以仓库 Pages 设置为准。

## 本机随时打开

在 macOS 上可**双击 [`打开直播演示.command`](./打开直播演示.command)**。它会在固定的 `http://localhost:5173/` 启动本机服务并打开浏览器；若服务已经运行，会直接打开网页，不会再启动一份。从 GitHub 网页下载源码后，如系统提示脚本不可执行，先在终端运行 `chmod +x app/*.command`。手动启动时请保留弹出的终端窗口，关闭窗口会停止服务。摄像头权限由打开网页的浏览器单独管理；第一次使用、清除站点数据或换浏览器后，仍需在浏览器中允许相机。

如需在 macOS 登录后自动提供本机演示，可运行 [`安装开机自启.command`](./安装开机自启.command)。它会重新构建当前源码，将网页快照和运行时复制到当前用户家目录，再安装登录服务；源码更新后须再次运行安装脚本以更新快照。取消时运行 [`关闭开机自启.command`](./关闭开机自启.command)。这些脚本只配置运行它们的 Mac，不会改变访问公开网页的测试者设备。

两个启动方式都固定使用 `localhost:5173`，端口被其他程序占用时不会悄悄换到 5174。一键开发启动会明确报错，开机服务则等待端口释放后再接管。在其他电脑上运行前，请先准备 Node.js 20.19+ 和网页依赖。

也可在本目录手动运行：

```sh
pnpm install
pnpm dev
```

在浏览器打开 **`http://localhost:5173/`**。默认尝试实时摄像头；若要用图像模拟，在直播框旁的“互动实验台 → 画面输入”中选内置表情图，或上传本地图片、播放 32.5 秒连续表情视频。`public/validation/covered-neutral.png` 是普通捂嘴负例；`public/validation/covered-laugh.png` 虽然视觉上像捂嘴笑，但当前模型在这张图上给出的双侧苹果肌上扬分数均为 0，所以在新规则下也是**遮挡边界样本，不应触发烟花**。`eye-smile.png`、`eye-laugh-open.png`、`squint-neutral.png` 分别用于核对闭嘴笑眼仍下雨、张嘴笑眼触发烟花、单纯眯眼不触发烟花。真人捂嘴大笑能否同时得到可靠的双侧苹果肌、笑眼和手部证据，仍需现场摄像头验证。回到实时画面可点实验台中的“返回实时摄像头”或重新打开摄像头开关。`localhost` 与 `127.0.0.1` 的摄像头站点权限可能分别保存；此前在 Codex 内置浏览器中，`localhost` 已成功取得相机画面，而 `127.0.0.1` 曾被站点授权拦截。用 `pnpm build` 检查静态打包，用 `pnpm test` 运行逻辑测试。人脸模型及 WASM 位于 `public/models/`、`public/wasm/`，无需从第三方地址下载推理资源。浏览器仍须允许网页使用摄像头。

**交付给别人时不能直接发 `localhost` 链接。** `localhost` 始终指向打开链接的那台电脑；别人电脑没有本项目和运行中的服务，就无法打开。在线交付使用仓库的 GitHub Pages HTTPS 地址，测试者需要在自己的浏览器中授权相机。构建产物可以放在域名根路径或 GitHub Pages 仓库子路径。

## 在直播间体验

1. **实时入镜与场景选择：**打开网页时会立即请求摄像头权限，只取视频、不录音。授权并连接后，画面显示本机镜头，页面开始寻找人脸与实时识别。实验台“触发场景”默认选自然互动；可改成礼物联动（对应互动礼物开启 8 秒窗口）、手动 PK 阶段或手动话题片段。后两种由旁侧按钮开启/结束，只模拟场景，不会自动听懂主播讲话。实验台“画面输入”中有摄像头开关：关闭会立即停止镜头并清空画面，重新打开会再次连接；关闭后也可点实验台上方的相机状态快速恢复。刷新页面默认重新开启。若权限被拒绝、镜头被占用或未见人脸，可在实验台查看提示、选择当前设备并重试。镜头临时不可用时网页也会以约 1.5–20 秒间隔自动重试。切到其他标签页时会释放摄像头；返回后自动尝试重连。
2. **表情触发：**闭嘴且嘴角上扬，即使眼睛也眯起，仍归为微笑：两朵完整的蓝紫小云从左右进入，在主播头顶汇成一朵大云；云内透光与细微电光先亮起，随后全画面下雨。发顶雨滴会在各自落点弹出小水珠，少数侧发落点会带出短水痕；虚拟镜头玻璃上出现雨滴撞击、汇流与下滑水线，五官附近逐颗降低遮挡。微笑保持期间，云只入场一次，雨持续落下。**张嘴且双眼都表现出笑意**并维持短暂多帧，会让白金色火核从画面四周分波升空，在主播头部后方及两侧绽放多种花型的彩色烟花；持续大笑期间按预制节奏继续发射，不重复播放一次性的入场。不要求先做闭嘴微笑，也不要求把嘴张得很大。较亮主火星碰到近似头缘后向侧方折返并产生局部二次碎火星，细小火星不会大量穿过面部。另一条烟花路径要求手确实遮住嘴、双侧苹果肌持续上扬且双眼表现笑意；普通捂嘴不触发。张嘴但眼神平常应视作说话候选，单纯眯眼或眉毛动作也不能触发烟花。短暂识别波动不应骤停效果；稳定回到平静后，雨云或烟花平滑收束，随后冷却 2 秒。微笑与大笑直接转换时，先收束当前效果，再凭新鲜表情帧启动另一效果，无须平静过渡。实验台显示当前识别与后台门控状态，不在直播画面展示倒计时。
3. **送礼与聊天：**底栏提供评论、表情、点赞、礼物和分享入口。点礼物入口打开托盘，选中后点“送出礼物”。礼物会给出即时反馈；若当前同类雨或烟花正在持续，匹配的 AR 加成可立即加入；不同类效果或冷却期间，则等待下一轮有效表情。体验币是模拟数值，不充值、不扣真实余额，也不会送入真实直播间。

**历史摄像头恢复记录（2026-10-19，旧界面）：**同一个 Codex 内置浏览器中，`http://127.0.0.1:5173/` 请求摄像头曾返回 `NotAllowedError: Permission denied`；改用 `http://localhost:5173/` 后，旧版页面显示“实时摄像头”“已识别到人脸”，并触发雨效。两个地址使用相同网页代码，故当时故障发生在浏览器的站点授权阶段。当前版本已另外完成 `localhost` 重载、服务接管、异常重启和摄像头开关后的实时画面复测；详见[验证记录](../docs/part2-demo-validation.md)。

## 实现与验证边界

Face Landmarker 输出人脸关键点与表情系数；项目综合**当前帧**的嘴角笑容、双颊变化、双眼笑意、下颌张开和相对嘴宽归一化的内唇间距，再用平滑、多帧防抖、滞回和冷却构造玩法状态。闭嘴嘴角上扬归为微笑，即使眼睛变窄也先进入雨效；张嘴笑与捂嘴笑是两条大笑候选路径。后者要求新鲜的手遮嘴证据、双侧苹果肌上扬、双侧笑眼，以及可见的嘴角笑弧或更强的双侧笑眼；须在独立的新鲜手部帧中持续确认，单凭遮嘴、眯眼或眨眼都不够。遮嘴时，模型偶然猜出“张嘴”也不能绕过这条严格路径。眉毛变化目前不参与触发；也不能只凭过去笑过的记忆触发。这些是表情动作的代理规则，**不是情绪诊断或笑声识别**；说话、打哈欠、眨眼、眯眼、揉鼻子及普通遮嘴等真人负例仍需摄像头实测。头部接触用随关键点移动的二维屏幕空间近似轮廓，不是精确头发分割或三维物理模拟。雨、烟花和礼物加成的形态、色彩与节奏是预制设计，运行时选择和模拟，不实时生成新的艺术效果。

视频识别优先在 Web Worker 中运行，不支持时退回主线程；推理按新帧限频，忙时不积压旧帧。播放期仍跟踪主播头部供雨滴接触和烟花碰撞使用，但不会启动另一段演出。桌面以手机比例展示直播间。内置浏览器已复测打开页面后自动显示实时相机画面并识别到人脸；真人不同表情、捂嘴笑与普通遮嘴、发型、快速移动和长期性能仍需现场复核。直播页内的图像模拟模式反复识别静态图或逐帧识别合成视频，能核对固定样本的触发链路；静态图没有真人表情变化、光照与头动，因此**不能作为实时摄像头触发准确率的证据**。详见[验证记录](../docs/part2-demo-validation.md)。

## 素材与来源

表情照片与合成视频的开发版副本位于 `public/validation/`，由本地开发版的“画面输入”菜单读取并交给同一模型；公开构建自动移除这些副本和菜单入口。顶部主播头像单独放在 `public/host-avatar.jpg`。提示词和用途见[测试素材说明](../docs/part2-test-assets.md)。当前雨云恢复为参考图之前的彩色透明 PNG，存放于 `public/effects/smile-rain-cloud-playful-v4.png`；制作与版本记录见[云素材记录](../docs/part2-cloud-asset-prompt.md)。网页控制云从两侧进入、在顶部合拢、轻微呼吸和淡出；雨丝、发顶水珠、侧发水痕与镜头玻璃水滴由有上限的粒子模拟。Face Landmarker 模型来自[Google 官方模型资源](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)，JS/WASM 使用 `@mediapipe/tasks-vision` 1.1.1。公开部署前仍需复核资产许可、匿名访问和真实移动设备体验。
